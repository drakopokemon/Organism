# 🧬 ORGANISM

Инфраструктура, которую не настраивают, а **выращивают**: из декларативного генома (цель + ограничения + пределы мутаций) клетки сами находят ресурсы, размножаются, лечатся, хранят данные и эволюционируют под нагрузку.
Ноль зависимостей — только JDK 21+ (лучше 25).

## Запуск

```bash
./run.sh                  # живая система + дашборд (браузер откроется сам): http://localhost:8080
./run.sh --selftest       # 13 проверок: инварианты, детерминизм, эволюция > статики, данные, реальные процессы
./run.sh --ab             # A/B: тот же мир и катастрофы, статика vs ORGANISM
./run.sh --manual         # HIGH-risk мутации ждут вашего Approve/Deny (есть «Approve all»)
./run.sh --symbiont       # реальные внешние процессы под управлением Symbiont Wrapper (kill -9 прямо в демо)
./run.sh --help
```
Windows: `run.bat` (те же аргументы). Docker: `docker build -t organism . && docker run --rm -p 8080:8080 organism`.
Флаги: `--ticks N --seed S --port P --tick-ms MS --no-ui --no-open --fast --no-chaos`.
Без `--ticks` система живёт, пока вы её не остановите (Ctrl+C); сценарий хаоса повторяется каждые 600 тиков.

## Что вы увидите
Дашборд: p99 vs SLA, трафик, популяция клеток по узлам, эволюция генов, fitness, стоимость, **карта шардов данных**, журнал решений. Сценарий хаоса детерминирован: всплески трафика, **падение узла** с самой плотной популяцией (с потерей его диска), **отравленная клетка**, воскрешение узлов. Организм переживает всё сам: споры прорастают на узлах-«опекунах», иммунные клетки изолируют больную клетку и заменяют её, потерянные реплики данных пере-создаются в других зонах.

Типичный A/B (700 тиков, seed 42):

| | статика | ORGANISM |
|---|---|---|
| fitness | 0.27 | **0.69** |
| тиков с p99 > SLA | 100 % | **16 %** |
| стоимость, $/ч | 2.11 | **1.25** |
| $ за 1M запросов | 1.34 | **0.63** |
| доступность | 89 % | **99.1 %** |
| потеряно шардов / записей | 0 / 0 | 0 / 0 |

(Самовосстановление данных — часть иммунной системы и работает в обоих режимах; эволюция выключается только у «статики».)

## Архитектура
```
Genome (sealed Objective / Constraint / Gene)        ← правила игры, exhaustive switch в движке
  └─ Organism: lockstep-тик, детерминированное применение намерений
       ├─ ProcessingCell  (виртуальный поток на клетку) метаболизм → эволюция → почкование/апоптоз
       ├─ StorageCell     реплика шарда на диске узла (полусинхронная репликация, лаг, ре-репликация)
       ├─ ImmuneCell      (по одной на узел) карантин → замена; опекун спор; ре-репликация данных
       ├─ Substrate       gossip (push-pull + heartbeat + подозрение), споры, выбор узла по ЛОКАЛЬНОМУ представлению
       ├─ Gate            Policy | Manual — human-in-the-loop для HIGH-risk генов
       ├─ Symbiont        обёртка над реальным внешним процессом (старт, health, backoff-рестарт, прокси)
       └─ Journal         JSONL: каждое решение с причиной (organism-journal.jsonl)
```
Клетки **решают** (параллельно, на виртуальных потоках), `Organism` лишь физически применяет их `Intent`-ы в детерминированном порядке — поэтому прогон воспроизводим по `--seed`.

**Эволюция:** канарейки (≤25 % популяции экспериментирует), парное сравнение с контрольной группой, статистический порог `gain > max(ε, stderr)`, правило 1/5, иммунные барьеры *до* запуска мутации (лимиты генома **и ёмкость RAM узла**), аварийный откат `ABORT`, горизонтальный перенос принятых генов, Human-in-the-loop для `Risk.HIGH`.

**Слой данных:** 24 шарда × R=3 в разных зонах. Запись подтверждается на лидере и одном фолловере, остальные догоняют с лагом. Смерть узла = потеря диска. Ре-репликацию запускает иммунная клетка узла **по своему gossip-представлению** (с реальной задержкой обнаружения), цель — зона без реплик этого шарда. Потеря *всех* реплик честно фиксируется как `DATA_LOST`.

**Symbiont Wrapper:** `./run.sh --symbiont` поднимает 3 настоящих внешних процесса (по умолчанию тот же JVM запускает `EchoService`; свой сервис: `--symbiont-cmd "python3 svc.py {port}"`, нужны `/health` и `/work`), гонит трафик, делает `kill -9` и показывает рестарты. Параметры обёртки (`timeoutMs`, `retries`) подбирает простая (1+1)-эволюция по реальной телеметрии; окна со сбоями в сравнении не участвуют (в демо p99 падает ~420 → ~70–110 мс).

**Наблюдаемость:** журнал JSONL; `GET /metrics` — формат Prometheus (скрейпится Prometheus-ом или OTel Collector-ом через `prometheus` receiver); `GET /stream` — SSE-снапшоты.

## Исправлено относительно исходной версии
* **Перерасход RAM узла** (найдено `--selftest`): мутация `cacheMb`, горизонтальный перенос генов и замена клетки чемпионом проверяли лимит одной клетки, но не ёмкость узла. Теперь запас узла делится поровну между клетками, перенос и замена проверяются точно. Цифры A/B из-за этого стали чуть скромнее — и честнее.
* При повторяющемся хаосе первый убитый узел никогда не воскресал — кластер вымирал бы. Теперь воскресают все.
* Ручной режим заваливал человека десятками предложений: очередь ограничена 6, добавлено «Approve all / Deny all».
* `run.sh` падал при нестандартном выводе `javac`; теперь работает и с JRE+модулем `jdk.compiler`.


## M4: Production Readiness (Edge & Chaos)
* **Disk Persistence (WAL):** `StorageHost` теперь пишет все мутации шардов в Write-Ahead Log (`data/wal/shard-N.wal`) через `FileChannel` с `force(false)`. При рестарте узла состояние мгновенно восстанавливается из WAL без полного anti-entropy sync с пиров.
* **Gossip Auth (HMAC-SHA256):** Все UDP-датаграммы `Wire` оборачиваются в `WireCodec` с MAC-подписью. Это защищает edge-флот от инжекта фейковых `ReplicateRequest` и `NodeFacts` без overhead полноценного mTLS/DTLS handshake.
* **Chaos CI:** В `.github/workflows/ci.yml` добавлен шаг `chaos.sh`, который поднимает 3 узла, эмулирует сетевой partition через `SIGSTOP`, и проверяет, что gossip и Storage восстанавливают консистентность после `SIGCONT`.

## Честно о границах
* Это **симуляция среды** (очередная модель + gossip + диски в процессе): эволюция видит только телеметрию, но настоящих сокетов между узлами нет. Реален только Symbiont. Следующий шаг — `Substrate` поверх реальных узлов (HTTP/gRPC gossip), `ProcessingCell` → нативный агент.
* Слой данных моделирует репликацию и отказоустойчивость (версии, лаг, потери), но не хранит реальные ключи/значения.
* Не проверялось в этой среде: `run.bat` (Windows), Docker-образ, `mvn -Pnative package` (GraalVM Native Image). Проверено: сборка/запуск на JDK 21 с `--enable-preview`; на Java 25 код не меняется, флаг не нужен.
* Журнал растёт бесконечно в режиме «живёт, пока не остановите»; для долгих прогонов ротируйте `organism-journal.jsonl`.
